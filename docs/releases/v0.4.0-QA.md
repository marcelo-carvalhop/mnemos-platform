# Mnemos v0.4.0 — QA record

This record describes the checks performed on the source package before the v0.4.0 handoff. It distinguishes static verification available in the packaging environment from builds that must be performed with the project's real toolchains.

## Verified in the packaging environment

The canonical schema validator completed successfully with 10 public JSON Schemas. The canonical Networking fixture validated as `mnemos.sync/v1` with exactly one deck, 10 cards and 10 card-state objects. `shared/generate.py --check` confirmed that generated contract files match `shared/contract.yaml`.

All GitHub Actions workflow YAML files, `compose.yaml` and `shared/contract.yaml` were parsed successfully. Python bytecode compilation completed for `backend/app` and `backend/tests`. Repository searches confirmed that the official mobile source no longer contains `StudyScreen`, the old `features/modes` surface, `providers_modes` or the removed `modes` package, and that the active app/firmware/example surfaces contain no OAB/concurso/vestibular/residência sample decks.

`git diff --check` against the v0.3.1 source baseline completed without whitespace errors. A repository staging simulation is also performed before packaging to confirm that ignored build products, caches, secrets and release binaries are not accidentally included.

During QA, a duplicate named argument (`enabled`) in the new Flutter Wi-Fi network list was found and corrected before release. Session-state deserialization in the CYD firmware was also made explicit for rating counters to reduce template/operator ambiguity in ArduinoJson builds.

## Not executable in this environment

The packaging environment does not contain Flutter/Dart or PlatformIO, therefore a real `flutter analyze`, `flutter test`, Android Gradle build and `pio run` cannot be claimed here. These commands are mandatory acceptance checks on the development workstation before tagging the release.

The backend test suite was invoked with `pytest -q`, but test collection could not start because the packaging environment does not contain project runtime dependencies `psycopg` and `anthropic`. This is an environment dependency failure, not a passing backend test result. CI installs the declared project dependencies and should be used as the authoritative backend test run.

## Required workstation acceptance

```bash
cd app/mobile
flutter pub get
flutter analyze
flutter test
flutter run -d <ANDROID_DEVICE_ID>
```

The physical Android acceptance should validate real Wi-Fi discovery, a dual-band SSID with a 2.4 GHz BSSID, AP-only provisioning, a remembered personal network and a direct BLE synchronization.

```bash
cd firmware/cyd
pio run
```

The firmware acceptance should additionally validate SoftAP association before any infrastructure connection, Wi-Fi OFF/ON persistence, known-network reconnection, session resume after restart, full-snapshot rollback behavior and BLE review acknowledgement.

```bash
cd backend
python -m pip install -e '.[dev]'
pytest -q
```

A database-backed CI or local PostgreSQL environment is required for the full backend suite.
